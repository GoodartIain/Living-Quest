## Known debt / defects

- Auth is a display name + bearer token in localStorage. Replace with real accounts (OIDC or email magic link) before any public hosting.
- Storage (PostgreSQL, `store.js`) runs as one app process per database and finds changes by comparing rows in memory; fine for a group's worlds, not for hosting many large worlds on one server. See ARCHITECTURE §11.
- `docker-compose.yml` and `Dockerfile` were written but not run (no Docker daemon in the build environment). The same app and migrations were tested against a local PostgreSQL 16.
- No rate limiting, no CSRF concern yet (bearer header, no cookies).
- Map images are external URLs, not uploaded assets.
- No URL routing: reloading the page returns to the world list.
- Characters, rules not automated (the SRD text is on the sheet; the player applies it): most class and subclass features beyond those listed as automated (e.g. Rogue Expertise, Champion Improved Critical, Extra Attack, Second Wind uses, Channel Divinity, Bardic Inspiration, Wild Shape, Focus Points), spell effects other than attack/damage/healing, multi-projectile spells (Magic Missile darts, Scorching Ray rays, Eldritch Blast beams: roll per projectile by hand), Two-Weapon and Great Weapon Fighting, Savage Attacker, Grappler and epic boon benefits other than the ability increase, tool proficiencies (Skilled picks skills only), Magic Initiate's spell list is not enforced, multiclass spellcasting uses one casting ability (the first caster class), prepared-spell limits are summed across classes, species traits are names only.
- Data to verify against the SRD 5.2.1 PDF: Trident (kept at 1d8 / Versatile 1d10, the dataset says 1d6 / 1d8), Sling (kept bludgeoning, the dataset says piercing), whether the 2024 Rogue skill list includes Performance (kept without it).
- Homebrew: species, backgrounds and classes only (no subclasses, feats, spells or items); a homebrew entry cannot be edited, only deleted and re-created while unused; homebrew classes have no starting equipment.
- Tabletop: no hex grid, no drawing tool, no dynamic lighting/line of sight, no HP/conditions on tokens without a character, controllers can only be set when the token is created (the API accepts changes, the UI does not offer it), measurement is not shared with other players.
- Broadcast: one on-air scene per campaign, no overlays, sponsor areas, player video tiles, HP bars or chat on stream, no stream delay, no cinematic/GM-directed camera, no direct RTMP egress (OBS capture only, by design for this milestone). The link key travels in the stream URL's query string (may appear in proxy logs); rotate it if it leaks.
- 3D: no doors or interactive objects (Milestone 10), no isometric or third-person camera, no lighting/shadows/line of sight (players see what fog reveals, as in 2D), no glTF models or 3D scene builder (tokens are capsules), no touch controls for first person (tactical works on touch), wall collision is client-side only (the server checks bounds and ownership, not walls), walls are horizontal/vertical grid lines only.
- Milestone 10 not done: 3D editing tools (placing walls, triggers and objects from the 3D view; walls and triggers are edited on the 2D board); triggers are not shown or usable in 3D yet. Adventures: no combat encounters inside an adventure (use a check node), no AI-facilitated adventures, no per-category delegation of GM approval, no time spent per node (the booked days cover the whole adventure), edits refused while someone is playing. Unfinished runs are abandoned at publish, not carried forward. Quests: no prerequisites, time limits or links to NPCs/locations; players cannot edit their own quest notes. Triggers: no conditions (e.g. needs a key item), no per-campaign used state (a once-trigger is used for the whole world).
- NPCs: no goals/utility layer, factions, NPC memories/knowledge or dialogue (Milestones 10–11); autonomy overrides per NPC only (not per campaign, region, settlement or faction); no significance gate yet because routine NPCs only do routine things (the gate arrives with goal-driven actions); movement is a jump between places/cells, no walking paths or travel time; scene tokens follow the world's first campaign when a world runs several; events have no duration of their own (each reaction has one); a GM dragging an NPC token is undone by the next clock move (use an override); routine steps are per place, so 'relocate' moves every step at that place.
- Downtime: unresolved activities are cancelled, not carried into the next window; no notifications (players reload the downtime screen; no live push); multi-character side-quest scenarios, NPC reactions and world events from downtime wait for Milestones 9–10; one open window per campaign; the GM can override a player's booking only by rejecting it; XP rewards are ignored in milestone campaigns (by design); the calendar has no named weekdays, leap years or holidays.
- Director Mode: refreshes by polling every 5 s; no downtime status, NPC simulation alerts, world events, scene sequencer, music/lighting/weather triggers, "View as player/spectator" (those depend on Milestones 7–11 or are later work).
- Voice/video: one call per campaign (no separate session rooms or breakout rooms), no spatial audio, no recording/transcription (needs consent records first), no server-side moderation beyond mute (kick/ban from the call), no TURN configured by default (strict firewalls), and production needs HTTPS/WSS in front of the app and LiveKit (see `docs/DEPLOY.md`). The compose file was not run (no Docker here); the same LiveKit binary and configuration were tested directly.
- Chat: no message editing, attachments, mentions/notifications or search; history shown is the last 200 messages per viewer; all messages stay in memory (the store's append-only path keeps writes cheap, but very long-running campaigns will need paging from the database).
- The stream URL carries the session token as a query parameter (browsers cannot set headers on EventSource); it can end up in proxy logs. Replace with a short-lived stream ticket when real auth lands.
- Search is substring over all pages in memory; fine for thousands of pages, add a Postgres full-text pre-filter beyond that.
